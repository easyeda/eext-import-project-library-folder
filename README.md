# 加载工程/库文件夹

嘉立创EDA / EasyEDA 专业版扩展：直接从未解压的**文件夹**导入工程（`.epro2`）与库（`.elibz2`）。

## 解决什么问题

很多企业客户的电脑装有本地文件加密系统（DLP / 透明加密），这类系统对压缩包**支持穿透加密**：zip 内部每个文件被单独加密；但**不支持穿透解密**。

于是出现下面的死循环：

1. 工程从 EDA 导出为 `.epro2` / `.elibz2`（本质是一个 zip）；
2. 加密系统把 zip 里的每个文件再次加密；
3. 之后用 EDA 导入这个文件时，EDA 解压出来的是**密文**，导入直接失败，且没有可用的错误提示。

本扩展把流程换了一条路：**绕开“压缩包”这一层，改为直接读文件夹**。

- 文件夹里的每个文件由操作系统在**读取时逐个解密**（加密系统对“单个文件读取”是支持的）；
- 扩展在**内存中**遍历、识别、重新打包成合法的 `.epro2` / `.elibz2`；
- 再把内存中的压缩包交给 EDA 官方导入接口。

因为压缩包**从未落盘**，不会被再次加密，EDA 拿到的就是明文包，导入恢复正常。

## 功能

| 功能 | 说明 |
| --- | --- |
| 拖拽 / 选择文件夹 | 弹窗支持把文件夹直接拖进去，也可点按钮打开系统文件夹选择框 |
| 自动识别嵌套 | 递归扫描文件夹树，自动识别多层级嵌套的工程 / 库文件夹，无需手工挑选 |
| 自动区分类型 | 含 `project2.json`（或 `*.epru`）→ 工程；含 `device2.json`（或 `*.elibu`）→ 库 |
| 内存打包 | 在内存中重建 `epro2` / `elibz2` 压缩包，全程不写本地磁盘，不会被再次加密 |
| 批量导入 | 一次识别出多个工程 / 库，勾选后逐个导入，带进度与失败原因 |
| 选择归属 | 导入前选择工作区 / 团队与目标目录，可选“导入后自动打开工程” |
| 原生压缩包兼容 | 文件夹里本来就有未加密的 `.epro2` / `.elibz2` / `.zip` 时，作为一项直接导入 |
| 全部文档类型可用 | 顶部菜单在 home / blank / 原理图 / 符号 / PCB / 封装 / PCB 视图 / 面板 / 面板视图中均可用 |
| 中英双语 | 跟随客户端语言自动切换 |

## 安装

1. 下载编译好的扩展包 `import-folder-to-easyeda_v1.0.0.eext`；
2. 打开 嘉立创EDA 专业版 → **设置** → **扩展** → **扩展管理器** → **加载扩展**；
3. 选择上面的 `.eext` 文件完成安装。

> 需要 嘉立创EDA 专业版 v3.2.0 及以上版本。“打开系统文件夹”按钮使用 `openReadFolderDialog`（v4.2+），
> 低版本会自动回退到浏览器标准的文件夹选择框，功能不受影响。

## 使用方法

### 准备：先准备好文件夹

1. **批量下载**：在 EDA 中把工程（epro2）或库（elibz2）下载到本地。批量导出可使用扩展
   [导出设计压缩包](https://jlc-ext.com/item/oshwhub/export-design-archive)。
2. **批量解压**：把工程与库压缩包解压到单独的文件夹中（每个工程 / 库一个文件夹）。
3. **选顶层文件夹**：导入时只需选择这些文件夹的顶层目录，扩展会自动识别其中所有工程与库。

### 1. 打开弹窗

在任意文档类型下点击顶部菜单：**加载工程/库文件夹 → 从文件夹导入工程 / 库...**

### 2. 选择文件夹

- 把**文件夹**直接拖进虚线区域；或
- 点击 **打开系统文件夹...** 在系统对话框中选择文件夹。

选中的文件夹可以是一整棵目录树，扩展会自动找出里面所有工程 / 库：

```
我的项目/
├── 电源板/                ← 工程文件夹
│   ├── project2.json
│   └── 电源板.epru
├── 历史版本/
│   └── 控制板V1/          ← 嵌套工程文件夹，同样会被识别
│       ├── project2.json
│       └── 控制板V1.epru
└── 常用库/                ← 库文件夹
    ├── device2.json
    └── lib2.elibu
```

### 3. 点「导入」开始分析

扩展会遍历文件夹树、识别出所有工程 / 库文件夹，并读出名称与内容统计：

- 工程：取 `project2.json` 里的 `title`
- 库：取文件夹名，并统计器件 / 符号 / 封装数量

### 4. 设置归属并确认

在右侧面板选择：

- **工作区 / 团队**：导入到哪个归属下（个人库也会出现在列表中）；
- **目标目录**：该团队下的目录树，可选团队根目录；
- **导入完成后自动打开工程**：勾选后，最后一个成功导入的工程会自动打开；
- **库中单个符号自动创建器件**：导入库时是否自动为单符号创建器件（默认勾选）。

确认后点 **开始导入**。

### 5. 查看进度

每个工程 / 库逐个导入，列表实时显示状态：

- `正在打包 x / y`：读取文件并在内存中重建压缩包；
- `正在导入...`：调用 EDA 官方导入接口；
- `导入成功` / `导入失败`（失败会显示具体原因）。

全部完成后点 **关闭**。

## 识别规则

判定以**目录**为单位，从浅到深递归扫描；命中后不再深入该目录（其整个子树作为该工程 / 库的内容）：

| 目录特征 | 判定 | 打包名 |
| --- | --- | --- |
| 存在 `project2.json` 或任意 `*.epru` | 工程 | `<名称>.epro2` |
| 存在 `device2.json` 或任意 `*.elibu` | 库 | `<名称>.elibz2` |
| 存在 `*.epro2` / `*.elibz2` / `*.zip` 文件 | 原生压缩包，原样导入 | 原文件名 |

`project2.json` 缺失时会自动补一个最小可用的元数据文件，避免因单个文件丢失导致整包导入失败。
`.DS_Store`、`Thumbs.db`、`__MACOSX`、`._*` 等系统垃圾文件会被忽略。

## 常见问题

**Q：为什么必须用文件夹，不能直接选 `.epro2` 文件？**
A：加密系统不支持“穿透解密”，压缩包里的文件对 EDA 而言是密文。文件夹方式下每个文件都是独立读取的，能正常解密。若文件夹里本来就有未加密的压缩包，扩展也支持直接导入。

**Q：会不会把我的文件写到磁盘？**
A：不会。文件内容只在内存中被读取与打包，压缩包以 `File` 对象直接交给 EDA 导入接口。

**Q：导入后工程名很奇怪？**
A：工程名优先取 `project2.json` 的 `title`，取不到时使用文件夹名；导入后可在工程树中重命名。

**Q：点了「导入」没反应，或提示 EDA 拒绝压缩包？**
A：请确认所选文件夹内确实包含 `project2.json` / `device2.json`。若压缩包来自其他软件或已损坏，EDA 会拒绝导入，请改用对应格式的官方导入流程。

**Q：能导入面板库吗？**
A：面板库（`panelLibs`）随库文件一起导入，扩展本身不做拆分。

npm run lint     # ESLint 检查
